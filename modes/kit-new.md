# /kit-new Mode — kit-skills v2.0

New project layer: 完全新建，从零建档，输入需求即开始。

---

## 定位

`/kit-new` 是 **全新项目的快速入口**。当用户有明确的新想法、新项目，不想走中间介入的状态检查时，直接触发建档流程。

**与 `/kit` 的区别：**

| | `/kit-new` | `/kit` |
|---|---|---|
| 触发场景 | "我想做一个xxxxx"、"新建项目"、"从零开始" | "继续 kit"、"接着做"、已建档项目的后续操作 |
| 状态检查 | **跳过**。不读取 `.plan/`、`.kit/` | **必须**。先报状态简报，检查漂移 |
| 头脑风暴 | 直接进入 brainstorm | 根据状态判断是否需要 |
| 适用阶段 | 项目生命周期的 **起点** | 项目生命周期的 **任意点** |

---

## 强制流程

```
用户输入需求 → Brainstorm（头脑风暴）→ 分类确认 → 生成 PRD → PM Audit → Spec Self-Review → YAGNI 门 → 用户确认
                                                    ↓
                                              生成 SPEC → PM Audit → Spec Self-Review → YAGNI 门 → 用户确认
                                                    ↓
                                              生成 CHECKLIST → PM Audit → Spec Self-Review → YAGNI 门 → 用户确认
                                                    ↓
                                              用户明确说"确认" → 才能进入 /kit-run
```

### Step 1: Brainstorm（头脑风暴）

**不可跳过**。即使用户说"我很清楚，直接做"，也必须确认以下三个问题：

1. **目标用户是谁？** — 谁会用这个东西？
2. **核心痛点是什么？** — 解决什么问题？不解决会怎样？
3. **预期输出是什么？** — 做完后用户能得到什么具体结果？

答不上来 = 不清楚，继续追问。

**头脑风暴偏好确认（首次使用）：**

```text
请选择你偏好的沟通方式：

[ ] "逐个确认"（推荐初学者）→ 我一次问一个问题，你回答后再继续
[ ] "一口气输出"（适合有经验用户）→ 我先输出完整分析，你再统一反馈
```

**分解门：项目太大先拆分**

如果用户描述包含多个独立子系统（如"做一个平台，含聊天、文件存储、计费"）：
- **必须立即 flag**："这个项目包含多个独立子系统，建议先拆分"
- 输出拆分建议：独立模块、依赖关系、构建顺序
- **禁止**：不拆分就直接细化所有模块的需求

### Step 2: 分类确认

按「需求识别」9 种类型分类，输出：
- 开发类型（skill/workflow/app/...）
- 预估规模（quick/standard/deep）
- 推荐技术路线
- **膨胀功能识别**：列出用户提到但可能不必要的功能，等用户确认后再砍
- 等用户说"确认"后再继续

### Step 3: 生成三件套（带确认门）

每阶段完整流程：

```
生成文档 → PM Audit → Spec Self-Review（4项自查）→ YAGNI 门（膨胀功能确认）→ 用户确认
```

**Spec Self-Review（自查 4 项）：**
1. 占位符扫描（TBD/TODO/待补充）
2. 内部一致性（PRD/SPEC/CHECKLIST 是否互相矛盾）
3. 范围检查（是否聚焦，有无塞入不属于当前阶段的内容）
4. 歧义检查（任何需求是否可被两种不同方式理解）

**YAGNI 门（需用户确认）：**
- AI 列出建议删减的功能，但**不自动删除**
- 用户说"同意删减" → 更新文档
- 用户说"保留全部" → 标记范围膨胀风险

**用户确认门（改进版）：**
- 不只是问"确认吗"，而是**让用户先看文件内容**
- 提供文档摘要，但鼓励用户打开文件 review
- 只有用户说"确认"才算通过

### Step 4: 用户最终确认

**必须得到用户明确说"确认"**，才能进入 `/kit-run`。

---

## 禁止行为

- 未头脑风暴直接生成 PRD
- 用户说"直接做"就跳过确认门
- 用 "ok"、"好的"、"行" 代替"确认"
- 在需求模糊时猜测并实施

---

## 输出

- `.plan/PRD.md`（用户确认后）
- `.plan/SPEC.md`（用户确认后）
- `.plan/CHECKLIST.md`（用户确认后）
- `.kit/config.json`
- 状态简报（建档完成时输出）
