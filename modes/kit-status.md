# /kit-status Mode — kit-skills v2.0

Status layer: 检查项目规范、方向漂移、归档需求。只读审计，不编码。

---

## 定位

`/kit-status` 是 **项目健康检查器**。当用户想了解"当前项目怎么样了"、"方向有没有偏"、"能不能归档"时，只读取状态、输出报告，**不写任何代码**。

**与 `/kit-run` 的区别：**

| | `/kit-status` | `/kit-run` |
|---|---|---|
| 触发场景 | "当前项目"、"检查状态"、"方向变了没" | "开始做"、"写代码"、"继续开发" |
| 写代码 | **绝不**。只读审计 | 是，执行开发 |
| 输出 | 状态报告 + 建议 | 代码 + 测试结果 |
| 用户确认 | 不需要（只读） | 必须（会改文件） |

## 强制流程

### Step 1: 读取项目状态

必须读取以下文件（缺失时标注）：

```text
.plan/PRD.md          → 目标、范围、验收标准
.plan/SPEC.md         → 技术方案、架构决策
.plan/CHECKLIST.md    → 任务进度
.kit/config.json      → 项目状态快照
.kit/version.json     → 版本合同
.kit/decisions.md     → 关键决策记录
.kit/blockers.json    → 阻塞项
README.md             → 项目入口
.workflow/README.md   → 流程状态（如有）
```

### Step 3: 方向漂移检测

对比用户当前请求与 `.plan/PRD.md`：

| 检查维度 | 一致 | 漂移 |
|---|---|---|
| 目标用户 | ✓ | 用户变了 |
| 核心功能 | ✓ | 功能改了 |
| 验收标准 | ✓ | 标准变了 |
| 技术路线 | ✓ | 架构改了 |

**漂移处理：**

- **无漂移**：输出"方向一致，可按计划继续"
- **轻微漂移**（实现方式调整）：标注建议，不阻塞
- **中度漂移**（功能扩展）：建议更新 SPEC/CHECKLIST
- **严重漂移**（目标/用户改变）：**必须经用户确认**，走「归档变更确认流程」

### Step 4: 归档检查（可选）

如果用户说"归档"或"整理"：

1. 检查是否有历史文件需要归档（`.plan/archive/`、`.test/ai/`）
2. 检查 Runtime Index 同步状态
3. 检查硬编码假设
4. 输出归档建议清单

**归档前必须经过用户确认。**

## 归档变更确认流程

当检测到严重方向漂移时：

```text
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
⚠️ 检测到方向变更
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

原目标: {来自 PRD}
新请求: {当前用户输入}

差异:
- 目标用户: A → B
- 核心功能: X → Y

建议:
1. 更新当前项目（归档旧 PLAN，重写新 PLAN）
2. 重开一个新项目（保持当前项目干净）

请选择:
- "更新当前项目" → 归档旧 PLAN → 生成新 PLAN → 用户确认
- "重开项目" → 保持当前项目 → 建议用 /kit-new
- "继续原目标" → 不修改 PLAN，继续执行
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

---

## 禁止行为

- **绝不写代码**。`/kit-status` 是只读审计模式。
- **绝不修改 `.plan/`、`.kit/`、README.md**。只输出报告。
- **绝不猜测用户意图**。检测到漂移时，必须问用户，不能替用户决定。

---

## 输出

- 终端状态报告（每次必输出）
- `.kit/status-reports/status-YYYYMMDD.md`（归档用，可选）
- 方向漂移报告（检测到漂移时输出）
